# 红线扫雷器 — 求职避坑桌面工具

> 产品方案文档 | 2026-08-09 | 个人项目

---

## Problem Statement

> **"How Might We"** — 如何让求职者在 30 秒内判断一家公司是否靠谱，避免踩坑？

求职市场信息严重不对称。公司包装得光鲜亮丽，求职者却看不到背后的劳动纠纷、离职率、真实口碑。现有工具要么只看工商数据（天眼查），要么用户评价分散（脉脉、看准网、知乎），缺乏一个聚合分析、给出明确判断的工具。

---

## Recommended Direction

**产品名：红线扫雷器（RedLine Scanner）**

核心体验：
1. 输入公司名称 → 3-5 秒 → 看到**红/黄/绿**安全评级
2. 下方是**结构化报告**：风险指标卡片（劳动纠纷、口碑评分、加班情况、社保合规等）
3. 底部有 **AI 对话窗口**，可以追问"具体说说加班情况""薪资水平怎么样"
4. 每个结论附带**信息来源链接**，透明可查

**为什么选这个方向？**
- 解决的是求职者最痛的"避坑"需求（你选的核心痛点）
- 极简入口（一次输入），丰富输出（报告+对话），兼顾效率与深度
- Python 生态在爬虫 + AI 领域最强，与你的技术偏好完全吻合

---

## Tech Stack

| 层 | 选型 | 理由 |
|----|------|------|
| GUI 框架 | **PySide6**（Qt for Python） | 比 Tkinter 美观专业，比 Electron 轻量，LGPL 协议友好 |
| 数据获取 | **requests + BeautifulSoup + Playwright** | requests 为主，JS 渲染页面用 Playwright 兜底 |
| AI 归纳 | **OpenAI API / 本地 Ollama** | 先用云端 API 验证效果，后续可切换本地模型降低成本 |
| 搜索引擎 | **DuckDuckGo / Bing API** | 聚合多源信息的第一步 |
| 数据存储 | **SQLite**（本地） | 缓存查询结果，避免重复爬取 |
| 打包分发 | **PyInstaller** | 打包成单个 .exe，无需安装 Python |

## MVP Scope（v0.1）

### ✅ 包含

- [ ] **输入框**：输入公司全称或简称
- [ ] **搜索引擎聚合**：通过搜索 API 获取目标公司的多源链接
- [ ] **关键平台解析**（优先级从高到低）：
  - `看准网` — 员工评分、点评
  - `知乎` — 相关问答和讨论
  - `天眼查/企查查` — 工商风险（公开页面）
  - `脉脉` — 员工匿名吐槽
- [ ] **AI 归纳引擎**：将碎片化信息输入 LLM，输出：
  - 🔴/🟡/🟢 综合安全评级
  - 3-5 条关键风险点 / 亮点
  - 2-3 句综合建议
- [ ] **报告仪表盘页面**：
  - 安全评级大卡片（颜色醒目）
  - 风险维度仪表（劳动纠纷、口碑、加班、社保、稳定性）
  - 信息来源链接列表
- [ ] **AI 追问对话**：底部对话窗口，可追问
- [ ] **查询历史**：本地 SQLite 记录，支持回看

### ❌ 不包含（v0.1）

- 多公司横向对比（v0.2）
- 企业监控/订阅推送（v0.2）
- 面试经验聚合（v0.3）
- 用户账号系统（永不做，本地工具定位）
- 移动端（永不做，专注 Windows 桌面）
- 自动获取招聘信息（可能 v0.3）
- 薪资精确数据（依赖付费接口，暂不做）

## Key Assumptions to Validate

- [ ] **假设 1：看准网/知乎/天眼查可以稳定获取数据** → PoC：写一个简单爬虫测试，看反爬强度
- [ ] **假设 2：LLM 能从搜索片段中给出合理判断** → 手工测试 5 家公司，对比 AI 输出 vs 已知口碑
- [ ] **假设 3：用户 3-5 秒能看懂报告** → 做 UI 原型给朋友试看，收集反馈
- [ ] **假设 4：API 调用成本可控** → 单次查询预计消耗约 2-3K tokens，约 ¥0.02-0.05，属于可接受范围

## Open Questions

- 是否需要支持模糊搜索公司名？（用户可能不知道全称）
- 是否需要缓存机制避免对同一公司短时间重复查询？
- 反爬对抗升级时，备选方案是什么？（纯搜索引擎摘要？）
- LLM 选择：先用云端 API 还是直接接本地 Ollama 模型？
