## 完成内容

### 🔒 API Key 加密存储（敏感信息保护）

用户要求对敏感信息（DeepSeek API Key）加密保护。经确认采用**设备密钥自动加密**方案（AES-GCM，用户无感），只加密 API Key 一项。

#### 实现
- **新增 [www/js/secure-store.js](www/js/secure-store.js)**：SecureStore 模块
  - 首次使用自动生成 256 位 AES-GCM 设备密钥，单独存放于 `zhajiaji_securekey`（与主数据分离，备份不会带出）
  - `saveApiKey()` / `getApiKey()`：加密保存 / 解密读取，明文只存在于内存
  - `migrateLegacyKey()`：启动时自动把旧版明文 Key 迁移为密文
  - 环境不支持 Web Crypto 时降级明文并告警
- **storage.js**：`aiConfig` 新增 `apiKeyEnc` 字段；`exportData()` 导出时剥离 API Key 明文与密文，备份文件不含任何密钥材料
- **app.js**：设置页不再回显明文 Key（显示"🔒 已加密保存"占位）；保存时加密写入；`testAIConnection()` 解密后仅在内存中使用；清空输入框 = 清除 Key
- **api.js / ai-engine.js / tasks.js**：改用 `SecureStore.getApiKey()` 解密读取；`isAIEnabled()` 兼容密文字段

#### 顺带修复
- **api.js `callLLM()`**：endpoint 已带 `/v1` 时不再重复拼接（原代码会拼出 `/v1/v1/chat/completions` 导致 AI 调用 404）。此 bug 之前未暴露是因为 AI 功能尚未真机联调。
